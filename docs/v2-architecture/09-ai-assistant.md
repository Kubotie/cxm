# 09. 画面内 AI アシスタント

全ページ共通の右サイドパネル。「**今見ている画面のことを何でも聞ける**」ことを狙いにしている。

実装:
- UI: `src/components/ai/index.tsx`（マウント）/ `ai-side-panel.tsx`（815 行）/ `ai-page-context.tsx`（登録機構）/ `ai-markdown.tsx`
- サーバー: `src/app/api/ai/chat/route.ts`（SSE）/ `src/lib/ai/chat-agent.ts`（エージェントループ）/ `data-sources.ts`（allowlist）/ `chat-store.ts`（履歴）/ `user-ai-prefs.ts`（設定）/ `openrouter-models.ts`

---

## 1. 仕組みの全体像

```
画面（Client）
  useRegisterAiPageContext({ pageId, title, description, snapshot, sources, hints })
        │  ← 画面が「今表示しているデータ」と「その取得元」を申告する
        ▼
AI パネル ──POST /api/ai/chat──► chat-agent
                                  ① snapshot をシステムプロンプトに載せる（最大 80,000 字）
                                  ② 足りなければ fetch_page_data で内部 API を GET
                                     （**リクエストの Cookie をそのまま転送**）
                                  ③ ツール結果を会話に足して再度モデルへ
                                  ④ テキストが出たら終了（往復は最大 6 回）
        ◄──SSE（thread / thinking / text / tool / done / error）──
        ▼
Vercel Blob に追記保存（ユーザー単位のスレッド）
```

`snapshot` は「AI に再取得させないため」に渡す。**画面が見ているものと AI が見るものを一致させる**のが目的。
`sources` は snapshot が丸められていたり、別の切り口が必要になったときの降り口。

### `loaded` フラグ

個社ページのようにタブ遅延読み込みをする画面は、開いていないタブのデータを持っていない。
`sources[].loaded: false` を申告すると、システムプロンプト上で「データ源 A: 取得済み」と「データ源 B: **未取得**」に分けて提示される。

> 一緒に並べると「画面が持っているデータ」と「まだ読んでいないデータ」の区別がつかず、モデルが未取得のものを取らずに総合判断を書き始める（実際に起きた）。

## 2. 画面側の申告（`useRegisterAiPageContext`）

v2 の主要 5 画面すべてが申告している。

| 画面 | pageId | snapshot の中身 |
|---|---|---|
| ホーム | `v2-home` | 担当 / レーン件数 / 対象社数 / 今日の要対応 / 利用の異変 / 業界ニュース（上位 20）/ バッチ更新状況 |
| 提案準備ボード | `v2-readiness` | レーン別件数 / 全件数 / **絞り込み後に画面に出ている items**（全件を渡すと AI が画面と違う母数で答える） |
| 個社ページ | `v2-company-detail` | 利用状況 / 時系列 / 顧客理解 / 準備度 / コミュニケーション（**取れているものだけ**）。未取得は hints に列挙 |
| プロジェクト分析 | — | 判定別件数・行 |
| Tier 3 / 設定 | — | 一覧と設定値 |

### 実装上のはまりどころ（コメントに残っている）

- **context を 2 つに分けている**（`actions` = 不変 / `meta` = 可変）。1 つにすると「meta 更新 → 参照変化 → cleanup で retract → 再登録 → …」で `Maximum update depth exceeded` になる。
- **snapshot は state ではなく ref に置く。** 毎レンダーで新しいオブジェクト参照になりうるため。パネルが snapshot を必要とするのは送信の瞬間だけ。

## 3. データ源カタログ（allowlist）

`src/lib/ai/data-sources.ts` に載っている **GET エンドポイントだけ**を叩ける。カタログはそのままシステムプロンプトに流し込まれるので、**ここに書いた説明文が AI のツール選択の判断材料**になる。

明示的な allowlist にしている理由:

> `/api/**` を GET 限定で全部許すと、副作用のある GET を巻き込む。
> 実例: `/api/batch/tier-sync`, `/api/batch/paid-watched-sync` は GET でもバッチ本体が走る（Vercel Cron からの GET を受けるため）。
> **「GET だから安全」はこの API 群では成り立たない。**

カタログには横断一覧（proposal-board / tier3-dashboard / light-watch / company-summary-list など）と個社系（usage / timeseries / readiness / profile / communications / people / actions / external-intel / 企業原本）が登録され、件数の多いものには `heavy: true` を付けてプロンプト側で注意を促す。

Cookie 転送が必須なのは、これらの API が `cxm_user_uid` でユーザーを解決するため（転送しないと「担当顧客」系が空を返す）。

## 4. 制限値

| 定数 | 値 | 意味 |
|---|---|---|
| `SNAPSHOT_CHAR_BUDGET` | 80,000 字 | 画面スナップショットのプロンプト搭載上限。超過分は切って深掘りに回す |
| `TOOL_RESULT_CHAR_BUDGET` | 40,000 字 | ツール 1 回の結果 |
| `MAX_TOOL_ROUNDS` | 6 | ツール往復の上限（無限ループと課金暴発の両方を止める） |
| `HISTORY_LIMIT` | 20 | モデルに渡す直近メッセージ数 |
| `maxDuration` | 300 秒 | `/api/ai/chat` |

## 5. システムプロンプトが強制していること

**質問を 2 種類に分けて手順を変える。**

- **点の質問**（単一の事実: 「この数字は何？」）→ スナップショットで答える。ツールを呼ばない。
- **面の質問**（判断・推奨・優先順位・原因）→ **答えを書き始める前に、判断に効く未取得ソースを揃える**（複数を並列に呼んでよい）。

面の質問での必須チェック:

1. データ源 B（未取得）に判断に関係するものが残っていないか。
2. **「〜すべき」と行動を勧める前に、既存のアクション・予定・履歴を必ず読む。** 既にあるものを「新規にやれ」と勧めるのは、この画面で最も価値を落とす失敗。
3. 人物名を出すなら連絡先データで実在と役割を確認する。
4. 「外部機会なし」「接点なし」のような**不在の主張**は、判定スコアの文言を転記せず、該当ソースを自分で読んで確認する。

回答ルール（抜粋）:

- **手順そのものを回答文に書かない**（「まず未取得データを確認します」等の実況禁止）。取得状況は UI が表示している。
- 日本語・結論先出し・簡潔。
- 数字は必ず出所を示す。データが無いことは「無い」と言う。推測で数字を作らない。
- 判定 API の説明文を自分で確認した事実として書かない。転記なら出典を明示する。
- **設定値の意味をフィールド名から推測しない。**（実例: `retentionDays: 0` を「保持しない」と読んだが正しくは「無期限」だった）
- 解釈と観測が矛盾したら**観測を優先**し、辻褄合わせの説明を作らない。
- **読み取り専用。** 作成・更新・削除・送信はできない。依頼されたら「画面のどのボタンから操作するか」を案内する。
- Markdown。表の直前には必ず空行（無いと表として描画されずパイプ記号が生で出る）。

利用者が設定画面で登録した「回答スタイル」（最大 600 字）は末尾に足されるが、**上のルールと矛盾する場合はルールが優先**する。

## 6. 履歴と設定（Vercel Blob）

### 履歴（`chat-store.ts`）

pathname: `ai-chat/{userKey}/{threadId}/{seq}.{updatedAtMs}.{msgCount}.{titleB64}.json`

**追記専用**。上書きしないのは Blob の `cacheControlMaxAge` が最小 60 秒で、送信直後のリロードで最大 1 分間古い履歴が返るため（チャット履歴としては壊れている）。

- 保存は毎回 `seq+1` の新しい pathname に put（内容不変 → CDN も新鮮）。
- 一覧は `list()` だけで完結する（タイトル・更新時刻・件数を pathname に埋めているので本文を 1 件も読まない）。
- 保存後、同一スレッドの古い版は削除する（失敗しても最大 seq が正なので無害）。
- seq 衝突時は put が 409 → 楽観排他としてそのまま再試行に使える。

各メッセージは `toolCalls[]`（叩いた内部 API パス・成否・要約）を保持し、**「何を見て答えたか」を UI で開示**する。

### 設定（`user-ai-prefs.ts`）

`instructions`（回答スタイル）/ `retentionDays`（0=無期限, 30, 90, 180, 365）/ `model`。
`staff_identify` に無い列へ PATCH すると 422 で落ちるため、履歴と同じく Blob に置く（追記専用・`list()` で最新 seq を選ぶ）。

モデル候補は OpenRouter `/models` を 1 時間キャッシュし、`anthropic/` かつ **tools 対応**かつ variant（`:batch` `:online`）でないものだけを出す。取得に失敗しても既定モデル 1 件で動く。

## 7. パネルの UI 挙動

- **オーバーレイではなく本文を押し出す。** 「画面の説明をさせる」用途なので、パネルを開いたまま元の画面を読めないと使えない。
- 押し出しはラッパー div の `padding-right` + `box-sizing: content-box`（`html`/`body` の padding・margin、ラッパーの margin はいずれもスクロール可能領域を作らず、本文がパネル下に潜って到達できなくなった）。
- 幅は 340〜760px でドラッグ変更、ビューポート幅の 50% を超えない。localStorage に保存。
- 本文の最小幅 `MIN_CONTENT_WIDTH = 820px`。下回ったら本文を潰さず横スクロールに逃がす（実測で残り 540px だと「PV消/費率」のように 1 文字ずつ折れた）。
- `/login` では出さない。
- 履歴の一覧から再開・改名・削除ができる。
